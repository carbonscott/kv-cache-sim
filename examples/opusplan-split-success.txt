# opusplan-split-success.txt -- the OPTIMISTIC opusplan case.
#
# Identical work to opusplan-baseline-opus.txt, but we plan on Opus then switch
# to Sonnet for the implementation -- and Sonnet gets it right first time. This
# is the best case for the split strategy. Compare its total against the
# baseline: the saving is almost nothing, because switching models invalidates
# the cache and the first Sonnet call must REWRITE the entire planning context.
#
# `user`/`tool` are free local appends; `call <out> [tu=N]` is the one billed API
# request. Each tool turn is TWO calls (a ~50-tok tool_use call, then the answer).

# --- Turn 1: plan on Opus (same as baseline): a tool_use call to Read 30K, then
# the 3K plan.
user 2000
call 50 tu=1
tool Read 30000
call 3000

# --- Hand off to Sonnet. SwitchModel zeroes the cache; the prefix survives, so
# the next call pays a full cache WRITE on the whole ~35K context at Sonnet's
# 1.25x. This one line is the entire "handoff penalty."
model sonnet-4.6

# --- Turns 2-5: implement on Sonnet. The first Sonnet call eats the rebuild; the
# rest are warm.
user 500
call 50 tu=1
tool Read 100
call 1500

user 500
call 50 tu=1
tool Read 100
call 1500

user 500
call 50 tu=1
tool Read 100
call 1500

user 500
call 50 tu=1
tool Read 100
call 1500

status
quit
